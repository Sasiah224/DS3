# For the undo/redo manager, I used a custom Stack class because it follows a Last-In, First-Out (LIFO) model. In a text editor, the action you just did is naturally the first one you want to take back when you hit undo. Using a `top` pointer with my `Node` class makes pushing and popping actions really straightforward. I also made sure that whenever a new action is performed, the redo stack clears out by starting a fresh `Stack()`, which keeps the history from getting messed up.

#For the help desk ticketing system, I went with a Queue because it uses a First-In, First-Out (FIFO) approach. Support lines need to be fair, so customers have to be helped in the exact order they arrive. My Queue class uses both `front` and `rear` pointers. When a customer is added via `enqueue`, they go to the back, and when they are helped via `dequeue`, they get removed from the front.

#Building these with custom nodes is a lot different than just using Python's built-in lists. Python lists are built on dynamic arrays, so if you add or remove items from the front, Python has to shift every single element over, which takes O(n) time. But with my linked nodes, adding and removing only involves updating pointers. That means my stack and queue operations all run in constant O(1) time without needing to shift memory around.
